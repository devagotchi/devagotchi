# Preserved-source inventory

Parent: [complete absorption plan](../absorb-preserved-sources.md).
Execution: [implementation packets](implementation.md).

The five `sN-files.json` files were generated by reading Git objects at the exact SHAs
recorded inside them. S1 covers its complete737-path tree; S2-S5 cover17,79,32,42 changed
paths respectively. Renames count as a deletion plus an addition. Total:907 file-change
records and100 commits. A file assigned to a packet is not implemented by that assignment.
Every row initially remains `unverified`.

`sN-surfaces.json` extracts literal route registrations, literal MCP names, exported Go
functions and Go test names from those files. Read dynamic registration loops, schemas,
presets and dispatch tables as well. These inventories guide review; they are not an
exhaustive semantic parser or proof that a capability works.

For each row, retain `path`, `change`, `blob`, `mode`, `kind`, `packet`; populate
`target_paths`, `evidence` and its disposition only after the actual comparison. A source
deletion is an intentional-review item, not permission to remove a same-named Rust file.
The original repositories and their dirty working trees are untouched.

The row's packet is its primary accounting owner. Shared migrations, presets, test harnesses
and shell files can support several packets; record all affected behaviors in its evidence.
In particular A00's documentation and schema inventory must distribute requirements to
runtime packets; assigning a document to A00 never retires what it specifies.

Allowed final dispositions and evidence requirements are in the parent plan. Preserve
historical test evidence as historical; it never becomes a current passing test receipt.
Never regenerate the files over completed manual mappings; regenerate a temporary inventory
and compare immutable fields if the source needs checking again.

Read-only verification (does not run CI or mark any row complete):

```text
py -3.11 scripts/check-absorption.py --go-source D:/localdev/agent-hub --rust-source D:/localdev/devagotchi-source-20261106
```

The checker verifies exact Git trees, deltas, blob metadata, commit sequences, packet
instructions and target/evidence structure. `--require-closed` additionally refuses open
rows; use it for delivery. Passing the ordinary inventory check proves accounting, not
semantic parity. Initial check: 100 commits and 907 records matched their Git objects;
all remained open.

Sequential delivery uses `--source S1 --require-closed` (then S2, etc.). This scopes
closure only; structure and supplied Git objects are still checked for all five sources.
The final `--require-closed` without `--source` requires the complete queue. A per-source
pass cannot establish final absorption or authorize deletion of any other source.

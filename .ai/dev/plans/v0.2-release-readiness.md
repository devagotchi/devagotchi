## Why v0.2.0

`v0.1.0` is already the published stable tag (2026-11-14). `Cargo.toml` is still `0.1.0`.
`v0.1.0-alpha.1` was the tag the changelog told the operator to cut, and it was never cut.
A prerelease tag does not move `:latest`. The changes since `v0.1.0` are a license change
and a larger tool and sign-in surface, which is a minor bump, not a patch. The operator
tags `v0.2.0` and bumps the workspace version in that commit.

## Risks and approved decisions

- The operator's rule is that no host, issuer, domain or region is hardcoded, and a solo
  user must be able to self-deploy. Sign in with Shippin is therefore on as a card and a
  switch, and off as a button, until the operator supplies an issuer (`/admin` or
  `install.sh --nomen`). A hardcoded `id.shippin.cloud` would violate that rule. S0, which
  would let a hub sign in with no client registered, is a Nomen change and is not done.
- `install.sh` used to rewrite tenancy to `single` and clear providers when those flags were
  omitted. Keeping the previous `.env` value is the fix. Passing `--google`, `--github` or
  `--nomen` still replaces the provider list, so an operator can remove one on purpose.
- The built-in marketing site still names `devagotchi.com` as the product's site. A
  self-hosted hub's public URL comes from `--domain` / `public_url`. Replacing the marketing
  copy is `--site`.

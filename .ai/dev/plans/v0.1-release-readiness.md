## Why v0.1.0

The first real release is `v0.1.0`, re-cut by the operator at the release commit (this work
on `main`). The earlier tag was not a baseline. `Cargo.toml` is already `0.1.0` and stays
there. `v0.1.0-alpha.1` was never tagged. A prerelease tag does not move `:latest`. The
notes stay under `## Unreleased`: the operator adds the release heading when tagging, and
this file already has a historical `## 0.1.0 - 2026-10-31` section. This change does not
create, move, or delete a tag.

## Risks and approved decisions

- The operator's rule is that no host, issuer, domain or region is hardcoded, and a solo
  user must be able to self-deploy. Sign in with Shippin is therefore on as a card and a
  switch, and off as a button, until the operator supplies an issuer (`/admin` or
  `install.sh --nomen`). A hardcoded `id.shippin.cloud` would violate that rule. S0, which
  would let a hub sign in with no client registered, is a Nomen change and is not done.
- `install.sh` used to rewrite tenancy to `single` and clear providers when those flags were
  omitted. Keeping the previous `.env` value is the fix. Passing `--google`, `--github` or
  `--nomen` still replaces the provider list, so an operator can remove one on purpose.
- The built-in marketing site still names `devagotchi.com` as the product's site. A
  self-hosted hub's public URL comes from `--domain` / `public_url`. Replacing the marketing
  copy is `--site`.

### Branch absorption procedure

1. Fetch every configured remote and inspect local branches/worktrees and open PRs in both
   repositories. Record remote main and every branch tip. An inaccessible remote or local
   checkout is **unverified**, never an empty successful inventory.
2. Order branches by dependencies. For each, record the PR or commits and classify it as
   already absorbed or needing integration. An ancestor check proves a normal merge;
   squash/rebase merges need the merged PR and a diff/patch review against main. A closed
   PR or similar title alone is insufficient.
3. Integrate unique work through scoped PRs, resolve conflicts against the current owners,
   run applicable checks and confirm each merge on GitHub. Do not discard a branch's work
   merely because it is stale or conflicts. Preserve unrelated dirty work.
4. Integrate AgentHub changes in its repository first and then update its pin in Devagotchi.
   Keep commercial hosting implementation in its designated module/private repository;
   absorbing work does not authorize copying private cloud code into the public release.
5. Repeat the inventory against the final remote main before declaring all branches
   absorbed. Delete only verified absorbed branches. Record unresolved work explicitly;
   a failed check is not permission to omit it or label it merged.
